1d:T1467,<h1>Grimoire — speak the app into existence</h1>
<p>Turn a plain-English description into a working app, pushed to a <strong>private
GitHub repo</strong> on the user&#39;s own account, complete with an <code>IMP_DOCS/</code> folder
(HANDOFF, TECH_SPEC, ARCHITECTURE + diagram, DESIGN_SYSTEM, ADRs, TODO,
CHANGELOG, PROMPT_TRAIL). This skill drives the Grimoire / AppBuilder engine
(repo: <code>github.com/Arnav1771/turmux_builder</code>).</p>
<h2>When to use</h2>
<ul>
<li>&quot;Grimoire, build me a …&quot;, &quot;build me an app that …&quot;, &quot;scaffold a … project&quot;</li>
<li>&quot;generate an app and push it to GitHub&quot;</li>
<li>&quot;update my generated repo to …&quot; / &quot;try an experiment on … in a new branch&quot;</li>
</ul>
<h2>Two ways to invoke (prefer the MCP tools)</h2>
<ol>
<li><strong>MCP tools (preferred)</strong> — if the Grimoire MCP server is connected, these
tools are available: <code>check_credentials</code>, <code>list_available_models</code>,
<code>build_app</code>, <code>update_app</code>, <code>experiment_app</code>. Use them directly.</li>
<li><strong>CLI fallback (Claude Code)</strong> — if no MCP server is present but the
<code>grimoire</code> command is installed, run it in the shell:
<code>grimoire keys</code>, <code>grimoire models</code>, <code>grimoire build &quot;...&quot;</code>.</li>
</ol>
<p>If neither is available, tell the user how to set it up (see
<a href="references/troubleshooting.md"><code>references/troubleshooting.md</code></a>) and stop.</p>
<h2>Bring-your-own-keys</h2>
<p>The engine needs the user&#39;s own <strong>GitHub token + username</strong> (to create and push
the repo) and <strong>one AI provider key</strong> matching the active provider. No Anthropic
key is required unless the user picks the <code>anthropic</code> provider. Details and the
key matrix: <a href="references/providers.md"><code>references/providers.md</code></a>.</p>
<h2>Workflow</h2>
<ol>
<li><strong>Check readiness.</strong> Call <code>check_credentials</code> (or <code>grimoire keys</code>). If it
reports missing keys, tell the user exactly what to set and stop — do not
attempt a build that will fail.</li>
<li><strong>Nail the spec.</strong> If the request is vague, ask 1–2 sharp questions (stack
preference? auth? persistence?). A precise prompt yields a better app — see
<a href="references/prompting.md"><code>references/prompting.md</code></a>. Do not over-interrogate.</li>
<li><strong>Pick provider/model (optional).</strong> Default is fine. Offer alternatives from
<code>list_available_models</code> only if the user cares. Pass <code>provider</code>/<code>model</code> to
the build tool when overriding.</li>
<li><strong>Build.</strong> Call <code>build_app(prompt=..., provider=?, model=?)</code> (or
<code>grimoire build &quot;...&quot;</code>). This can take a minute — say so.</li>
<li><strong>Report.</strong> Return the <code>repo_url</code> (and <code>live_url</code> if deployed), the tech
stack, file count, and point the user at <code>IMP_DOCS/HANDOFF.md</code> for how to run
it. Note repos are <strong>private</strong> by default.</li>
<li><strong>Iterate.</strong> For changes to an existing repo use <code>update_app(repo_url, changes)</code>; for a throwaway trial use <code>experiment_app(repo_url, branch, changes)</code> (non-destructive — new branch).</li>
</ol>
<h2>Ground rules</h2>
<ul>
<li><strong>Never ask for keys in chat.</strong> Credentials live in the MCP server&#39;s env (or
the user&#39;s <code>.env</code>) — never request or echo them in the conversation.</li>
<li><strong>Confirm before overwriting.</strong> <code>update_app</code> edits an existing repo; make sure
the user means that repo. Prefer <code>experiment_app</code> for anything speculative.</li>
<li><strong>Report honestly.</strong> Relay the real <code>repo_url</code> and any partial failures from
the tool result; don&#39;t claim success you can&#39;t see.</li>
<li><strong>No AI attribution</strong> on anything you commit on the user&#39;s behalf.</li>
</ul>
<h2>Examples</h2>
<ul>
<li>&quot;Grimoire, build a FastAPI bookstore API with SQLite.&quot; →
<code>check_credentials</code> → <code>build_app(prompt=&quot;a FastAPI bookstore API with SQLite&quot;)</code>
→ report repo URL + <code>IMP_DOCS/HANDOFF.md</code>.</li>
<li>&quot;Use Claude to build a React dashboard.&quot; →
<code>build_app(prompt=&quot;a React dashboard ...&quot;, provider=&quot;anthropic&quot;)</code>.</li>
<li>&quot;Add dark mode to <a href="https://github.com/me/my-app">https://github.com/me/my-app</a>.&quot; →
<code>update_app(repo_url=&quot;https://github.com/me/my-app&quot;, changes=&quot;add a dark-mode toggle&quot;)</code>.</li>
</ul>
