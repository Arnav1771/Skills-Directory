# aaxon_skill_scripts

Windows batch (`.bat`) and shell (`.sh`) scripts to **register** and
**invoke** all 66 AAxon skills referenced across the five delivery-phase
prompt files, against the Claude API via the `aa-skills` CLI
(`aa_skills_framework`, included alongside this folder).

Generated from:
- `skill_catalog.md` — the 70-entry AA skill catalog (source of Purpose,
  Inputs, Outputs, Constraints, etc.)
- `01-establish-strategy.md` … `05-simplified-ai-operations.md` — the five
  phase prompt files (source of the 67 sample-prompt invocations)

67 total skill invocations across 66 unique skills — `eval-harness` is
invoked once in Phase 03 (Platform Enablement) and again in Phase 05
(Simplified AI Operations); every script checks the registry before
registering, so it will not be uploaded twice.

## Prerequisites

```bash
pip install -e ../aa_skills_framework
export ANTHROPIC_API_KEY=sk-ant-...      # Windows: set ANTHROPIC_API_KEY=sk-ant-...
aa-skills credits set-balance --amount <what you've topped up>
```

## What each per-skill script does

Take `windows/02-data-readiness/01-context-fabric.bat` (or the `.sh`
equivalent) as the pattern every script follows:

1. Confirms `ANTHROPIC_API_KEY` is set.
2. Checks the local registry (`registry/aa_skill_registry.json`, created
   on first use — **not** the same file as `aa_skill_registry.reference.json`,
   see below) for whether `context-fabric` is already registered.
3. If not: uploads `skills_bundles/context-fabric/SKILL.md` via
   `aa-skills register-skill`.
4. Invokes it with `aa-skills invoke --prompt-file
   prompts/02-data-readiness/01-context-fabric.txt`, in a session named
   after the phase (`aaxon-02-data-readiness`), so files generated by one
   prompt in a phase are available (via `--use <alias>`, added manually)
   to later prompts in the same phase.
5. Runs the pre-flight credit check and post-call balance print built
   into `aa-skills invoke` automatically — no extra flags needed.

## Running things

**One skill:**
```
windows\02-data-readiness\01-context-fabric.bat
./shell/02-data-readiness/01-context-fabric.sh
```

**A whole phase, in prompt order:**
```
windows\02-data-readiness\00-run-phase.bat
./shell/02-data-readiness/00-run-phase.sh
```

**Everything, all five phases in order:**
```
windows\00-run-everything.bat
./shell/00-run-everything.sh
```

Running everything end to end will consume real API credit across all 67
invocations — check `aa-skills credits show` before committing to that,
and consider running phase-by-phase instead so you can review output
between phases (which is also what the source prompt files themselves
instruct — see the `NEXT` / `CONFIRM` gating logic each phase file
describes for human-in-the-loop review).

## Folder layout

```
aaxon_skill_scripts/
  skills_bundles/<slug>/SKILL.md        # 66 auto-generated skill bundles
  prompts/<phase>/<NN>-<slug>.txt       # 67 prompt files, extracted verbatim
  windows/<phase>/<NN>-<slug>.bat       # 67 per-skill Windows scripts
  windows/<phase>/00-run-phase.bat      # 5 per-phase Windows runners
  windows/00-run-everything.bat         # 1 top-level Windows runner
  shell/<phase>/<NN>-<slug>.sh          # 67 per-skill shell scripts
  shell/<phase>/00-run-phase.sh         # 5 per-phase shell runners
  shell/00-run-everything.sh            # 1 top-level shell runner
  registry/aa_skill_registry.reference.json   # human-readable reference only —
                                               # NOT the live registry the
                                               # scripts read/write (that file
                                               # is created fresh on first run)
```

## Important limitations — read before running against production data

1. **The generated SKILL.md bundles are contracts, not implementations.**
   Each one is built from the catalog's documented Purpose / Capabilities /
   Inputs / Outputs / Constraints — it is *not* the skill's original source
   code or detailed procedural logic (that lives in AA's AAxon framework
   source, which was not part of what was uploaded here). Claude will
   execute against the documented contract; review each bundle before
   relying on its output for a real engagement, and expect to iterate on
   the SKILL.md content once you see how Claude interprets it.

2. **Prompt files are extracted verbatim from the phase markdown**,
   including their own internal `### Inputs` / `### Execution` sections
   that assume a local project filesystem (`artifacts/openspec.yaml`,
   `specs/knowledge.md`, etc.) — because the Claude API's code-execution
   container starts empty per session, you'll generally need to pass the
   relevant prior artifacts in via `--file` / `--use` (see the parent
   `aa_skills_framework/README.md`) rather than relying on the prompt's
   own filesystem-path references resolving automatically.

3. **The `eval-harness` duplication** reflects two distinct catalog
   entries (`EvalHarness` and `EvalHarness (Optimization Layer)`) that
   were treated as the same underlying skill for registration purposes
   since both prompt occurrences invoke the literal string `eval-harness`.
   If these are meant to be functionally distinct skills in AA's actual
   framework, split `skills_bundles/eval-harness` into two bundles and
   update the phase-05 script's `SKILL_NAME` accordingly.

4. **Credit checking is local-estimate only** (see
   `aa_skills_framework/README.md` section 0) — running all 67 invocations
   unattended without a seeded balance will only warn, not block.
