## Overview

This package contains the complete set of Operate-phase skills for the AAxon AI-Native SDLC framework. Each skill is a structured AI accelerator designed to be invoked by a POD Lead using Claude. Skills generate executable production artifacts — scripts, configs, dashboards, and reports — that give a 1 POD Lead + 2 builder team full production operations capability without a dedicated ops or data science function.

Every skill contributes structured signals to `operate/feedback-loop-triggers.yaml`, the document that seeds the next Monday's sprint planning session with production evidence. This closes the loop between what was planned, what was built, and what is actually happening in production.

## Installation

### Step 1 — Copy skill files to your project

```bash
# From this package root, copy .claude/ to your AAxon project root
cp -r .claude/ /path/to/your-project/.claude/

# Copy the operate/ directory
cp -r operate/ /path/to/your-project/operate/
```

### Step 2 — Verify prerequisites exist

```bash
# Check required upstream files
ls artifacts/openspec.yaml
ls artifacts/deploy-manifest.yaml    # May not exist yet — skills handle this
ls artifacts/roi-brief.md            # Required for ValueTracker only
```

### Step 3 — Install Python dependencies

All generated monitoring scripts require:

```bash
pip install anthropic requests pyyaml
```

Optional, stack-specific:
```bash
# For Prometheus integration
pip install prometheus-client

# For Datadog integration
pip install datadog

# For database-backed business metrics (ValueTracker)
pip install sqlalchemy psycopg2-binary  # or your DB driver
```

### Step 4 — Set environment variables

```bash
export ANTHROPIC_API_KEY="sk-ant-..."      # Required for DriftGuard scoring
export ALERT_WEBHOOK_URL="https://..."     # Slack / Teams webhook
export METRICS_ENDPOINT="http://..."       # Prometheus / observability endpoint
```

## Usage — Running a Skill

Every skill follows the same three-stage interaction pattern:

```
1. INVOKE   → Say the trigger phrase to Claude
2. ELICIT   → Answer structured Q&A (validated inputs, with EDIT capability)
3. CONFIRM  → Type CONFIRM at the confirmation gate to generate artifacts
```

### Recommended Activation Order

For a new deployment, run skills in this order:

```
1. ControlPlane     ← Establish cost ceilings first (RuntimeIQ reads these)
2. RuntimeIQ        ← Set up SLA monitoring and scaling
3. DriftGuard       ← Set up drift detection (needs observability stack)
4. RunbookSynth     ← Generate runbooks (reads deploy manifest + design)
5. IncidentLens     ← Set up incident intake (Mode B requires history)
6. ValueTracker     ← Set up ROI measurement (requires baseline capture first)
7. ExperimentOps    ← Design experiments (requires stakeholder sign-off)
```

**RuntimeIQ** (SLA monitoring + auto-scaling):

run RuntimeIQ

**DriftGuard** (model output drift detection):

## Elicitation Protocol — How Skills Ask Questions

All skills use a structured Q&A protocol:

1. Questions are asked sequentially, one at a time
2. Some questions are conditional (`depends_on`) — only asked if a prior answer triggers them
3. All answers are validated before proceeding
4. After all questions are answered, the skill presents a **Confirmation Gate** — a structured summary of all collected values
5. Type `CONFIRM` to proceed, or `EDIT Q<number>` to revise a specific answer

**Example interaction:**
```
Skill: What observability stack is in use?
       a) Prometheus + Grafana
       b) Datadog
       c) OpenTelemetry
       ...

You: a) Prometheus + Grafana

Skill: Provide the metrics endpoint URL:

You: http://prometheus.monitoring.svc.cluster.local:9090

[... more questions ...]

Skill: ──────────────────────────────────────
       RuntimeIQ Configuration Summary
       Observability stack: Prometheus + Grafana
       Metrics endpoint   : http://prometheus...
       ...
       Type CONFIRM to proceed or EDIT Q2 to change.

You: CONFIRM

Skill: [Generates all artifacts to operate/runtime-iq/]
```

## Adding New Operate Skills

To create a new Operate-phase skill:

1. Copy `.claude/SKILL-TEMPLATE.md` to `.claude/<new-skill-name>/SKILL.md`
2. Complete all `[REQUIRED]` sections in the template
3. Add the skill's feedback loop contribution key to `operate/feedback-loop-triggers-schema.yaml`
4. Add sample_input and sample_output examples
5. Register in this README's Skill Inventory table

## Troubleshooting

| Problem | Solution |
|---|---|
| `openspec.yaml not found` | Run SpecFlow (Planning phase) to generate the locked sprint spec |
| `deploy-manifest.yaml not found` | Skills will elicit runtime details inline via Q&A |
| Skill elicitation not triggering | Use exact trigger phrases listed in each SKILL.md |
| `ANTHROPIC_API_KEY` not set | Set the env var before running DriftGuard (uses Claude API for scoring) |
| Monitoring script can't reach metrics endpoint | Verify observability stack is running; check network access from script location |
| `feedback-loop-triggers.yaml` overwritten | Each skill only writes its own top-level key; multiple skills are safe to run concurrently |
